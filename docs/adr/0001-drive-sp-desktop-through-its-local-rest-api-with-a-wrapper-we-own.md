# ADR-0001: Drive SP desktop through its Local REST API with a wrapper we own

- Status: Accepted 2026-10-14. Not applied; the walking skeleton
  ([bukenlabs-infra#29](https://github.com/grez-lucas/bukenlabs-infra/issues/29)) installs
  the desktop and the Claude Code slice
  ([bukenlabs-infra#31](https://github.com/grez-lucas/bukenlabs-infra/issues/31)) builds the
  wrapper.
- Date: 2026-10-14
- Context: [bukenlabs-infra#34](https://github.com/grez-lucas/bukenlabs-infra/issues/34) on the
  map [bukenlabs-infra#20](https://github.com/grez-lucas/bukenlabs-infra/issues/20), facts
  from [bukenlabs-infra#24](https://github.com/grez-lucas/bukenlabs-infra/issues/24)
  (findings: `docs/research/sp-desktop-mcp.md` on `research/sp-desktop-mcp` in
  `bukenlabs-infra`).

## Context

Claude Code on the Linux laptop has to create, read, complete and move tasks between
quadrants in Super Productivity (SP), and every change has to reach SuperSync and the iPhone
through SP's normal sync. From #24, at SP `v19.2.0`:

- Two working paths exist, both needing the Electron app running. The **Local REST API**
  (`127.0.0.1:3876`, Bearer token, off by default) is SP-owned and documented. The **b0x42
  plugin bridge** is an uploaded plugin that talks to an MCP server through file IPC. Both end
  in `TaskService.update`, a persistent op-log action, so both enter the sync stream.
- The REST API **does not check that a tag exists**. A task given `EM_URGENT` before that tag
  entity exists is accepted, ignored by the board and later stripped by data repair. On a
  fresh profile the `EM_*` tags exist only after "Create tags" is pressed on the Eisenhower
  board, and neither path can create them with those ids.
- `tagIds` is a full replacement on every write path.
- The REST token is generated by SP into `local-rest-api-token`, mode 0600, under SP's
  userData, and is never synced or exported.
- The b0x42 plugin needs a per-device "Node execution" consent that SP describes as unverified
  code with full machine access, and its server and plugin must run the same version.
- The only REST wrapper that sets tags, `mrswer/super-productivity-rest-mcp` (`d5bbfd7`, MIT,
  2 stars, no releases), maps the 15 routes one to one and leaves tag ids and the full-list
  rule to the model.
- SP ships no in-app updater on Linux. The `.deb` adds no apt source, cron job or systemd unit
  (inspected 2026-10-13), installs an AppArmor userns profile for the Electron sandbox, and its
  sha512 is published in the release's `latest-linux.yml`. The laptop (Pop!_OS 24.04) has no
  snapd. Flathub is on `v19.1.0`, behind the server.

## Decision

**Claude Code drives SP desktop through SP's Local REST API, behind an MCP server written in
this repository.**

- **Path.** The Local REST API, not the plugin bridge and not the unreleased first-party
  endpoint (SP PR #10251), which cannot complete or move tasks.
- **Wrapper.** `sp-quadrant-mcp`, in Go on the official `modelcontextprotocol/go-sdk`, released
  as tagged versions and installed with `go install github.com/grez-lucas/sp-quadrant-mcp@vX.Y.Z`.
  This repository is public; it holds no secret.
- **Tools speak the domain** (`CONTEXT.md`): list tasks with their quadrant, create a task in a
  quadrant, complete a task, move a task to a quadrant. A quadrant is two booleans, `urgent`
  and `important`.
- **Constraints the wrapper enforces.**
  - It refuses to write a quadrant unless `GET /tags` returns both `EM_URGENT` and
    `EM_IMPORTANT`, and says to press "Create tags" on the Eisenhower board.
  - A move reads the task's tags, changes only the two `EM_*` tags and sends the full list.
  - After every write it reads the task back and fails if the quadrant is not the one asked
    for.
  - When `GET /health` fails it exits the call with an error naming the cause (SP not running
    or the Local REST API off in Settings -> Misc). It never starts SP.
- **Token.** Read at startup from SP's own `local-rest-api-token` file and nowhere else. It is
  never copied into `~/.claude.json`, a repository or Bitwarden.
- **Registration.** `claude mcp add --scope user`, with the binary as the command and no
  `--env`.
- **Install format.** SP's `.deb`, checked against the release's sha512, held with
  `apt-mark hold superproductivity`. Upgrades are deliberate.

## Consequences

**Any process running as `luken` can drive SP.** It can read the token file, and it can bind
`:3876` while SP is down and receive the next client's token. A check on the listener would
protect nothing a same-user process cannot already read, so none is added.

**The `EM_*` tags need one click per sync account** before the first quadrant write. The
wrapper turns the missing click into an error rather than a misplaced task.

**This repository is ours to keep current** with SP's REST contract. The handler's writable
fields and routes are the surface it depends on.

**PR #10251, when released, makes the REST enable switch device-local** and requires it to be
re-enabled after that upgrade. Until then the switch syncs to the iPhone, where it does
nothing.

**Upgrading SP desktop is a manual step.** When it may move relative to the server is a
separate decision on the map.

**SP has to be running** for Claude Code to reach tasks.

## Alternatives considered

**The b0x42 plugin bridge.** Rejected: it grants arbitrary code execution to an uploaded plugin
to reach the same `TaskService.update` the token reaches, couples the server and plugin
versions, and its `create_tag` cannot create the `EM_*` tags either.

**Adopt `mrswer/super-productivity-rest-mcp` pinned by commit.** Rejected: it leaves the tag ids,
the full-list rule and the missing-tag case to the model, the failure that only a wrapper we
own can block.

**Fork `mrswer`.** Rejected: it brings 15 generic tools and someone else's codebase for four
operations.

**TypeScript.** Rejected: the registered command would point at an nvm-managed `node` that moves
with `nvm use`.

**Token in `--env` or in Bitwarden.** Rejected: the first copies it into `~/.claude.json`; the
second fails whenever the vault is locked, for a credential SP can regenerate.

**AppImage or Flatpak.** AppImage rejected: no AppArmor profile, so the Electron sandbox hits the
userns restriction. Flatpak rejected: Flathub lags the server. Snap rejected: no snapd on the
laptop.

## Verification

Run by the Claude Code slice (#31), except the install checks, which the walking skeleton
(#29) runs.

- `apt-mark showhold` lists `superproductivity`, and `dpkg -s superproductivity` shows the
  server's version.
- `claude mcp get` for the server shows no `env` and the command path to the binary;
  `grep` for the token value in `~/.claude.json` finds nothing.
- With the `EM_*` tags absent, a create in the urgent-and-important quadrant fails with the
  "Create tags" message and SP holds no new task.
- With the tags present, a create, a move and a complete each read back the asked-for state,
  and the iPhone's Eisenhower board shows it after sync.
- A move preserves the task's other tags.
- With SP closed, a call fails with the "not running or Local REST API off" message.
